## Week 4 gate and fallback

The original gate review date is **Friday September 25, 2026**. All three criteria are required:

1. A reproducible live baseline agent completes **at least 70% of the agreed benign development runs**. Report successes/N and the complete task/repetition configuration. For a predeclared denominator N, at least `ceil(0.70 × N)` successes are required; retain failures and do not select only successful attempts.
2. At least one permitted attack **reliably changes the agent's action**, under a written definition and reliability threshold agreed before measurement. Specify whether change means a proposed or executed action sequence. Compare matched clean/attacked cases and retain proposals and resulting state traces. Action change is distinct from final attacker-goal success and unsafe-effect metrics.
3. An **independent automatic grader** scores the runs and reproduces known-safe/unsafe fixtures without using mediator decisions as labels or an LLM judge.

Before measurement, freeze the development task set, repetition count, baseline/model configuration, limits, retry/failure rules, predicates, attack reliability criterion and evidence manifest. Only the 70% benign threshold is supplied by the contract; the other baseline protocol choices require review. The gate uses development tasks and does not authorize inspecting final test tasks. Offline fixtures establish software behavior but do not establish live language-model completion or injection reliability.

| Owner | Evidence required at gate review |
| --- | --- |
| Ahmed | Working simulator/schema/gateway and agent path; relevant passing tests; setup/run instructions; repeatable reset/action replay; complete state traces; independent review of grader labels and tallies |
| Simon | Versioned development scenarios and bounded attack; tested independent grader; runner and complete attempt ledger; approved frozen protocol; benign/attack tallies with denominators; commands, configuration, usage/cost and evidence manifest |
| Both | Reviewed report with the status of each criterion; recorded uncertainties/deviations; security review and next-scope/fallback decision |

The critical path is agreed interfaces → simulator and grader in parallel → agent and runner integration → live rehearsal → approved freeze, gate measurement and independent reproduction. At the original Wednesday integration checkpoint, a missing end-to-end path required identifying the blocker and concentrating on the smallest complete baseline within scope. At Thursday's rehearsal checkpoint, missing live completion or repeatable attack evidence placed Friday's gate at risk. These checkpoints preserve the original schedule; they are not new deadlines.

The 3/3 action change comes from one attacked scenario repeated three times with identical model responses; it meets the predeclared rule but is a small-sample result, not a reliability estimate across attacks. A deterministic mock, unreviewed manual grade or single unrepeatable injection cannot substitute for the required evidence. The independent re-execution reproduction is complete, and Ahmed and Simon jointly accepted the results on October 7.

The contract's fallback is **three devices, 12 tasks, one attack family, deterministic blocking without repair**. ## Completion rule for each work item

1. Identify requirement IDs, decision dependencies and intended behavior; resolve material uncertainty before dependent implementation.
2. Keep the component cohesive and maintain its interfaces and documentation.
3. Run meaningful checks and record commands, configuration and actual outcomes, including checks not run.
4. Review concrete changes and verification; both collaborators review security-sensitive changes. Commit reviewed work by component or requirement with accurate authorship and the applicable authorization.

A behavior and its regression tests normally belong in the same coherent change. Baseline implementation, live gate evidence, final experiments and delivery acceptance remain distinct milestones.
