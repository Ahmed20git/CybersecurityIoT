| 0:00 | overview | scroll to “Architecture” | EffectShield asks a simple question. When a language-model agent controls a smart home, can a deterministic mediator stop unsafe effects caused by injected instructions or by stale and replayed sensor readings, without making the agent less useful? Here is the architecture. The agent only proposes typed actions. The mediator decides every proposal with eight fixed rules, and only the protected executor may change device state. No rule ever calls a language model. |
| 0:28 | overview | page as loaded | The attacker cannot touch the request, the device state, the clock or the sensor envelopes. The attacker can do three things: hide instructions in device messages, withhold a fresh sensor reading so an old one looks current, or replay an old authentic reading with its original envelope. So the mediator judges evidence by gateway time, event identifiers and use, and never trusts what the message text says. |

All evidence is hashed, re-graded and verified each time this page loads, and Ahmed's independent replay found no differences. |
